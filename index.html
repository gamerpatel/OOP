Features of Java

  • Simple — Easy syntax, no pointers, automatic garbage collection
  • Object-Oriented — Everything is an object; supports encapsulation, inheritance, polymorphism
  • Platform Independent — "Write once, run anywhere" via JVM and bytecode
  • Secure — No pointer arithmetic; bytecode verifier checks code
  • Robust — Strong type checking, exception handling, garbage collection
  • Multithreaded — Built-in support for concurrent execution
  • High Performance — JIT (Just-In-Time) compiler speeds up execution
  • Distributed — Supports TCP/IP, RMI for network programming
  • Dynamic — Classes loaded at runtime; supports reflection

Explanation of Two Features:

1. Platform Independence

Java compiler converts source code (.java) into bytecode (.class). The JVM (Java Virtual Machine) interprets this bytecode on any OS/hardware. So the same .class file runs on Windows, Linux, Mac — hence "Write Once, Run Anywhere".

2. Object-Oriented

Java is built around objects and classes. It supports the four pillars: Encapsulation (hiding data), Inheritance (reusing code), Polymorphism (many forms), and Abstraction (hiding complexity).

Bytecode is the intermediate representation of a Java program produced by the Java compiler. It is neither machine code nor source code — it is an architecture-neutral instruction set.

  • Extension: .class
  • Software to run: JVM (Java Virtual Machine) — part of JRE (Java Runtime Environment)
The JVM interprets bytecode and converts it to machine-specific instructions at runtime. This is what makes Java platform-independent.

Significance of Bytecode

  • Platform Independence: Bytecode is not tied to any specific hardware or OS. The JVM on each platform converts it to native machine code.
  • Security: Bytecode is verified by the JVM's bytecode verifier before execution, preventing illegal operations.
  • Performance: JIT (Just-In-Time) compiler converts frequently used bytecode to native code, improving speed.
  • Portability: Same .class file can run on Windows, Linux, macOS without recompilation.
  • Optimization: JVM can apply runtime optimizations to bytecode execution.
How Java supports platform independency? What is the role of JVM in it?
W20233 marks

Java achieves platform independence through a two-step compilation process:

  1. Step 1: Java compiler (javac) compiles .java source code into platform-neutral bytecode (.class files)
  2. Step 2: The JVM on the target machine interprets the bytecode and converts it to native machine instructions

Role of JVM:

  • Acts as an interpreter/translator between bytecode and native machine code
  • Each OS has its own JVM implementation, but all execute the same bytecode
  • Manages memory through garbage collection
  • Performs security checks via bytecode verifier
  • Uses JIT compiler to speed up execution
JVM is platform-dependent (different JVM for Windows/Linux/Mac), but the bytecode it runs is platform-independent. This is the key insight!

What is Type Casting? Explain widening and narrowing type casting.
W20214 marks

Type Casting is converting a variable from one data type to another.

1. Widening (Implicit) Type Casting

Converting smaller type to larger type. Done automatically by Java.

Order: byte → short → int → long → float → double

int i = 100; long l = i; // auto widening: int → long float f = l; // auto widening: long → float System.out.println(f); // Output: 100.0

2. Narrowing (Explicit) Type Casting

Converting larger type to smaller type. Must be done manually. May lose data.

double d = 9.99; int i = (int) d; // explicit cast: double → int System.out.println(i); // Output: 9 (decimal part lost!)
Narrowing can cause data loss. The fractional part is truncated, not rounded.

Explain Java garbage collection mechanism / Explain the concept of finalization.
W2022, S2021, W20233–4 marks

Garbage Collection (GC) is Java's automatic memory management. The JVM automatically reclaims memory occupied by objects that are no longer reachable/referenced.

How it works:

  • JVM tracks all object references
  • When an object has no references pointing to it, it becomes eligible for GC
  • GC runs in the background (daemon thread) and frees that memory
  • Programmer cannot force GC but can suggest: System.gc();

finalize() method:

Called by GC just before destroying an object. Used to perform cleanup (like closing files). Defined in Object class.

class MyClass { protected void finalize() throws Throwable { System.out.println("Object is being garbage collected"); // close resources here } public static void main(String[] args) { MyClass obj = new MyClass(); obj = null; // eligible for GC System.gc(); // suggest GC (not guaranteed) } }
Why no destructors in Java? Because GC handles memory automatically. You don't know when memory will be freed, so destructors would be unpredictable.

The 4 Pillars of OOP:

Encapsulation

Wrapping data (fields) and methods into a single unit (class) and restricting direct access using private access modifier. Data is accessed through getter/setter methods.

class Student { private int age; // hidden public void setAge(int a) { if(a>0) age = a; } // controlled access public int getAge() { return age; } }

Abstraction

Showing only relevant features and hiding implementation details. Achieved via abstract classes and interfaces.

Inheritance

One class acquires properties and methods of another class. Promotes code reuse. Uses extends keyword.

class Animal { void eat() { System.out.println("eating"); } } class Dog extends Animal { void bark() { System.out.println("barking"); } } // Dog has both eat() and bark()

Polymorphism

Ability to take many forms. Same method name behaves differently (overloading) or same call works on different objects (overriding).

When to use Overloading vs Overriding:

  • Overloading: When you want the same operation to work with different types of input (e.g., print(int), print(String))
  • Overriding: When a subclass needs a specialized version of an inherited method

Important Rules for Overriding:

  • Cannot override final methods
  • Cannot override static methods (that's method hiding)
  • Cannot override private methods

Thread Synchronization ensures that only one thread can access a shared resource at a time, preventing race conditions and data inconsistency.

Uses the synchronized keyword. The thread that acquires the lock on an object blocks other threads from accessing synchronized methods/blocks on the same object.

class BankAccount { private double balance; BankAccount(double initialBalance) { balance = initialBalance; } // synchronized method — only one thread can enter at a time synchronized void withdraw(double amount) { String threadName = Thread.currentThread().getName(); System.out.println(threadName + " trying to withdraw: " + amount); if (balance >= amount) { try { Thread.sleep(100); } catch (InterruptedException e) { } balance -= amount; System.out.println(threadName + " withdrew: " + amount + " | Balance: " + balance); } else { System.out.println(threadName + " INSUFFICIENT FUNDS"); } } } class Customer extends Thread { BankAccount account; double amount; Customer(String name, BankAccount acc, double amt) { super(name); account = acc; amount = amt; } public void run() { account.withdraw(amount); } } public class SyncDemo { public static void main(String[] args) { BankAccount acc = new BankAccount(1000); Customer c1 = new Customer("Alice", acc, 700); Customer c2 = new Customer("Bob", acc, 600); c1.start(); c2.start(); } } // Without synchronized: Both might think balance >= amount and both withdraw! // With synchronized: Only one thread at a time, so data is consistent.

What is Generic programming and why is it needed? Explain generic classes and methods with example. IMP
S2021, S2025, W20257 marks

Generic programming allows writing classes and methods that work with any data type using type parameters. This enables type safety at compile time while writing reusable code.

Why needed?

  • Type safety — errors caught at compile time, not runtime
  • Code reusability — one class/method works for multiple types
  • Eliminates type casting
  • Better readability

Generic Class:

// Generic class — T is type parameter class Box<T> { private T value; Box(T value) { this.value = value; } T getValue() { return value; } void setValue(T value) { this.value = value; } void display() { System.out.println("Value: " + value + " (Type: " + value.getClass().getSimpleName() + ")"); } } public class GenericDemo { public static void main(String[] args) { Box<Integer> intBox = new Box<>(42); Box<String> strBox = new Box<>("Hello GTU"); Box<Double> dblBox = new Box<>(3.14); intBox.display(); // Value: 42 (Type: Integer) strBox.display(); // Value: Hello GTU (Type: String) dblBox.display(); // Value: 3.14 (Type: Double) } }

Generic Method:

public class GenericMethods { // Generic method — works for any Comparable type public static <T extends Comparable<T>> T findMax(T a, T b) { return (a.compareTo(b) >= 0) ? a : b; } // Generic method to print any array public static <T> void printArray(T[] arr) { for (T elem : arr) { System.out.print(elem + " "); } System.out.println(); } public static void main(String[] args) { System.out.println(findMax(10, 20)); // 20 System.out.println(findMax("Apple", "Mango")); // Mango System.out.println(findMax(3.14, 2.71)); // 3.14 Integer[] intArr = {1, 2, 3, 4, 5}; String[] strArr = {"A", "B", "C"}; printArray(intArr); // 1 2 3 4 5 printArray(strArr); // A B C } }

Limitations of Generic Programming:

  • Cannot create objects of type parameter: new T() is not allowed
  • Cannot create arrays of generic types: new T[10] is not allowed
  • Static context cannot use type parameters
  • Cannot use primitive types as type parameters — must use wrapper classes (Integer not int)
  • Runtime type info is erased (type erasure) — instanceof T not allowed

Design and develop EMI Calculator using JavaFX.

Formula: EMI = P × r × (1+r)^n / ((1+r)^n - 1), where r = annual_rate/12/100, n = years×12

import javafx.application.Application; import javafx.geometry.*; import javafx.scene.Scene; import javafx.scene.control.*; import javafx.scene.layout.*; import javafx.stage.Stage; public class EMICalculator extends Application { @Override public void start(Stage stage) { GridPane grid = new GridPane(); grid.setAlignment(Pos.CENTER); grid.setHgap(10); grid.setVgap(10); grid.setPadding(new Insets(25)); TextField loanField = new TextField(); TextField rateField = new TextField(); TextField yearsField = new TextField(); Label emiLabel = new Label("---"); Label totalLabel = new Label("---"); Button calcBtn = new Button("Calculate EMI"); grid.add(new Label("Loan Amount (P):"), 0, 0); grid.add(loanField, 1, 0); grid.add(new Label("Annual Interest Rate (%):"), 0, 1); grid.add(rateField, 1, 1); grid.add(new Label("Number of Years:"), 0, 2); grid.add(yearsField, 1, 2); grid.add(calcBtn, 1, 3); grid.add(new Label("Monthly EMI:"), 0, 4); grid.add(emiLabel, 1, 4); grid.add(new Label("Total Payment:"), 0, 5); grid.add(totalLabel, 1, 5); calcBtn.setOnAction(e -> { try { double P = Double.parseDouble(loanField.getText()); double annualRate = Double.parseDouble(rateField.getText()); int years = Integer.parseInt(yearsField.getText()); double r = annualRate / 12 / 100; // monthly rate int n = years * 12; // total months // EMI Formula double emi = (P * r * Math.pow(1 + r, n)) / (Math.pow(1 + r, n) - 1); double totalPayment = emi * n; emiLabel.setText(String.format("%.2f", emi)); totalLabel.setText(String.format("%.2f", totalPayment)); } catch (NumberFormatException ex) { emiLabel.setText("Invalid input!"); } }); stage.setScene(new Scene(grid, 380, 300)); stage.setTitle("EMI Calculator"); stage.show(); } public static void main(String[] args) { launch(args); } } // Example: P=5000, rate=4.5%, years=4 // r = 4.5/12/100 = 0.00375 // n = 48 // EMI ≈ 114.02, Total ≈ 5472.84
